prevalence_CDW_AND_MVP:
Numbers of reports where the “Microscopic Description” was run (and the number which are positive) for Gemma-2-9B-SPPO and Llama-3-8B, as well as the counts for when “both” are positive or “either” are positive. The Method column combines the task, cohort, and source for a unique entry for each row. Task column represents the diagnostic task. Cohort is either IBD patient population or non-IBD. Source represents the data source, either MVP or CDW. N_llama3_8B and N_gemma2_9B_SPPO columns are the number of reports run for Llama-3 and Gemma-2, respectively. N_overlap is the number of reports where both models are run. Note that this is not the number of reports validated, but the larger set in which the models. The validation sets are a subset of this larger set of N_overlap. N_pos… represents the number which are positive of those run for each model, including “both” as the requirement that both Llama-3 and Gemma-2 respond “Yes” and “either” as the requirement that either Llama-3 and Gemma-2 respond “Yes”.  The final two columns represent the mean and median number of input characters for the Microscopic Description sections of the reports seen by the models.

validation_CDW_AND_MVP:
The de-identified validation results for all tasks, cohorts, and sources for all models. The first six columns are model binary outputs, either 1/0 or TRUE/FALSE, with 1 and TRUE both representing a model answer of “Yes” and vice versa. NA values in these columns mean that the model was not run for this report. The “_full” suffix in columns 5 and 6 denotes that the input report was the full pathology report and not the Microscopic description section. BDJ, AD, HE, and LJ are the reviewers, with their validation results indicating a lack of the diagnosis (0) or the presence of the diagnosis (1). HE only reviewed cases where BDJ and AD disagreed. LJ only reviewed cases where HE was unsure. NA values in the reviewer columns indicate that the person did not review that report. The consensusValidation is the consensus of the reviewers, which was determined as follows: If BDJ and AD agree, their response is the consensus. If not, HE resolves the dispute and that answer determines the consensus. If HE is unsure, LJ determines the consensus. BDJ_full represents the validation result for the full pathology report, which sometimes differed from the Microscopic description section (see Supplementary Figure S6). BDJ reviewed the full pathology reports in cases where either Llama-3-8B or Gemma-2-9B-SPPO had a different answer seeing the full report than the same model did seeing the Microscopic description section. Otherwise, BDJ_full was set to the value of the consensus validation. The task column is the diagnostic task evaluated. The cohort column represents the patient population (IBD vs. non-IBD). The nchar and ncharFull columns are the number of characters, using the nchar() function in R, of the Microscopic description section and full pathology report, respectively. The source column indicates if the data comes from MVP or CDW.

all_results:
The main results shown in the paper are contained in this csv. This csv is also converted to a “.xlsx” file for the creation of the main paper tables, as well as S3-S5 and S8. This csv is produced by the R script “make_csv_from_raw_data.R”. Column names are generally self-explanatory, but we define some terms which may be confusing here:
-	w: prevalence
-	lb (lb_boot): lower bound of 95% confidence interval by bootstrapping
-	ub (ub_boot): lower bound of 95% confidence interval by bootstrapping
-	upperBound_analytical (lowerBound_analytical): For NPV and PPV, this is the binomial 95% confidence interval bounds. The wider of the two bounds (analytical or bootstrapping) is used as sometimes (i.e., when NPV and/or PPV = 1) bootstrapping will lead to confidence intervals that are too narrow.
-	MCC: Matthew’s correlation coefficient
-	N_<>_<>_<>: The number of reports where the conditions listed between the underscores are true.
-	BDJ_<pos/neg>_AD_<pos/neg>: The 2x2 confusion matrix (pos/pos, pos/neg, neg/pos, neg/neg) entries for the two reviewers BDJ and AD.
-	conditionalModel: This is the model used for conditioning/stratifying for validation. Typically, this was Llama-3-8B,  and we reviewed N reports where Llama-3-8B was positive and N reports where it was negative. In IBD-CRC in MVP, the conditional model was “either” because we reviewed all reports where either Llama-3-8B or Gemma-2-9B-SPPO were positive, and N reports where both were negative.
See the R script (“make_csv_from_raw_data.R”)  or ask us (brian.d.johnson97@gmail.com) if anything is unclear.
